TSUNAGI Explorer — Deployment Notes
=====================================

Page:    /explorer/
Source:  web/explorer/index.html
Model:   Static HTML with dynamic JSON fetch

=== DEPLOYMENT ===

1. Copy to server:

   sudo cp web/explorer/index.html \
     /var/www/tsunagi/explorer/index.html

2. Ensure the directory exists:

   sudo mkdir -p /var/www/tsunagi/explorer

3. Reload nginx if needed:

   sudo nginx -t && sudo systemctl reload nginx

=== DEPENDENCY ===

This page fetches /status.json on every load and every 10 seconds.
The status JSON must be available at:

  /var/www/tsunagi/status.json

If status.json is missing or unreachable, the page displays a
graceful "Telemetry Unavailable" state with dimmed panels.

The status JSON is generated by:

  scripts/generate-status-json.sh

See scripts/README-status-json.txt for automation details.

=== EXPECTED JSON FIELDS ===

The explorer reads all 20 fields from status.json:

  network, slot, block, tip_hash, fwd, back, utxo, tps,
  shadow_enabled, primary_mode, status, updated_at,
  tx_count, utxo_consumed, utxo_produced, utxo_delta,
  coverage_found, coverage_total, fallback_used, tip_age_seconds

Missing or null fields display as "—".

=== NGINX LOCATION (if not already configured) ===

  location /explorer/ {
      try_files $uri $uri/ /explorer/index.html;
  }

This is typically covered by the existing site-wide configuration.

=== DIFFERENCES FROM STATUS PAGE ===

The Explorer page provides the same data as /status/ but with:
  - A prominent "Latest Decoded Block" hero panel
  - Section-grouped card layout (Chain, Ledger, Persistence, Health)
  - Larger visual footprint for primary chain metrics
  - 3-column grid for health indicators

Both pages read from the same /status.json source.
