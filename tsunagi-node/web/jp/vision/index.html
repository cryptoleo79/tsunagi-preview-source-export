TSUNAGI Vision

強靭なネットワークのための独立インフラ

§1 TSUNAGIが存在する理由

Cardanoの長期的な回復力は、実装の多様性に依存しています。単一のノード実装のみによって運営されるネットワークは、単一のコードベース、単一の前提、単一のエンジニアリングチームの優先順位にシステミックリスクを集中させます。TSUNAGIは、独立した実装を提供するために存在します — 第一原理から、異なるトレードオフで、異なる言語で、独立したエンジニアによって構築されたもの。

目標は既存のインフラを置き換えることではありません。別の視点、別のコードベース、別の検証済み動作をネットワークの基盤に加えることで、エコシステムを強化することです。

§2 独立した実装の重要性

分散システムの歴史は、一貫した教訓を示しています：単一の実装に依存するネットワークは、障害時にのみ顕在化する脆弱性を持つということです。すべてのノードが同じコードを実行する場合、すべてのノードが同じ盲点を共有します。コンセンサスロジックのバグは、単に一つの参加者に影響するだけでなく — ネットワーク全体に同時に影響します。独立した実装は、異なるコードベースが同じ欠陥を共有する可能性が低いため、この種の障害に対する構造的防御を提供します。

Ethereumのマルチクライアントモデルの採用は、この原則を大規模に実証しています。実行層とコンセンサス層の複数の独立した実装 — Geth、Nethermind、Besu、Erigon、Lighthouse、Prysm、Tekuなど — を維持することで、Ethereumエコシステムは、モノカルチャーでは検出されなかったであろうプロトコルの曖昧性やコンセンサスのエッジケースを繰り返し発見してきました。クライアントがトランザクションの結果やブロックの有効性について異なる見解を示す場合、その不一致自体が価値を持ちます：仕様で明示されなかった前提を浮き彫りにするからです。

TSUNAGIは、この哲学をCardanoにもたらします。Zigで独立して構築され、既存のCardanoノード実装とのコード祖先を一切持たないTSUNAGIは、プロトコルの完全に独立した解釈を提供します。このプロジェクトは日本から開発されており、Cardanoのインフラ景観に地理的・文化的多様性を加えています。異なるエンジニアリングの伝統は、異なるアーキテクチャの直感、異なるテスト哲学、異なる障害モード認識を生み出します。この多様性は偶然ではなく — 独立した実装がネットワークに貢献する価値の一部です。

§3 決定論的インフラ

決定論は、TSUNAGIアーキテクチャの基盤的制約です。同一の入力は、無条件で同一の出力を生成しなければなりません。隠された状態なし、実行パスを変更する暗黙の設定なし、システムレベルのエントロピーやタイミングへの依存なし。台帳パイプラインのすべての状態遷移は入力の純粋関数であり、すべての出力は同じ初期条件が与えられれば再現可能です。

この方針はすべてのアーキテクチャ上の決定に影響を与えます。台帳パイプラインは設計上モジュラーです — デルタ抽出、状態適用、アンドゥ管理、永続化はそれぞれ独立してテスト可能なサブシステムであり、明確に定義された入出力境界を持ちます。ブロックが処理されると、結果の台帳状態は前の状態とブロックの内容の決定論的関数となります。ロールバックが発生した場合、アンドゥパスはバイト単位で正確な以前の状態を生成します。近似も結果整合性もありません。システムは正しい結果を生成するか、明示的に失敗します。

決定論は単なる技術的特性ではなく、運用上の保証です。TSUNAGIを運用するオペレータは、ノードの動作を確信を持って推論できます。二つのノードが同じチェーンを処理すれば、同じ状態に到達します。状態が永続化され、後で復元された場合、再開された計算は中断されなかった実行と同一の結果を生成します。この予測可能性はデバッグ作業の一カテゴリ全体を排除し、非決定論的インフラには不可能な方法でシステムを監査可能にします。

§4 オペレータ第一のシステム

TSUNAGIは、自らのインフラを理解したいオペレータのために設計されています — 単に運用するだけでなく、内部状態を把握し、動作を診断し、出力を信頼できるように。このプロジェクトは、通常時はブラックボックスとして機能し、障害時に不透明になるという一般的なインフラのパターンを拒否します。TSUNAGIのすべてのサブシステムは、自らを説明するよう構築されています。

この原則は、いくつかのメカニズムを通じて具体的に現れています。KAGAMIスナップショットは、ノードの内部状態 — 台帳位置、同期進捗、サブシステムの健全性、リソース使用率 — のポイントインタイム表現を、構造化された機械可読形式で提供します。構造化ジャーナルは、現在の状態に至った一連のイベントを再構築するのに十分な詳細で、ノードの運用履歴を記録します。カバレッジ追跡は、どのプロトコルパスが実行されたかを測定し、テスト済みのものと未検証のものについて確信を与えます。

この哲学はエラー処理と障害モードにも及びます。TSUNAGIが異常に遭遇した場合、黙ってリトライしたり、一般的なログメッセージの背後にエラーを飲み込んだりしません。何が試みられていたか、どの前提条件が満たされていたか、何が具体的に問題だったかの文脈とともに障害を報告します。オペレータは、ノードが何をしているか、なぜそうしているかを推測する必要があるべきではありません。自らの動作を説明できないインフラは信頼できないインフラであり、TSUNAGIは可観測性を後から追加する機能としてではなく、コアなアーキテクチャ要件として扱います。

§5 MUSUBI — 接続型インフラ

MUSUBI （結び）は、結合、接続、そして接続を通じた創発を意味します。日本の伝統において、結びは物事を関係に導く生成的な力を表します — 単なるリンクではなく、接続の行為を通じて新しいものを生み出すこと。

TSUNAGIの長期的ビジョンにおいて、MUSUBIはシステム、チェーン、実行環境間の接続型インフラの可能性を表しています。これは製品発表でもプロトコル仕様でもありません。研究方針です。

ブロックチェーンエコシステムは、相互運用性に向かって収束しています。境界を越えて状態を検証できない孤立したチェーンは、ユーザーとアプリケーションが実行環境間の流動的な移動を要求するにつれ、摩擦が増大します。状態遷移を独立して検証できる決定論的インフラ — リモートの証明を信頼するのではなく、計算を再現することで — は、信頼ドメイン間の不可欠な接続組織となる可能性があります。あるチェーンからの証明を受け取り、独立して維持された状態と照合し、決定論的な出力を生成する能力は、TSUNAGIのアーキテクチャが支援するよう設計された操作そのものです。

TSUNAGIの基本的な決定 — 決定論的実行、モジュラー状態管理、独立して検証可能な台帳遷移、構造化された状態表現 — は、接続型インフラの偶然の前提条件ではありません。境界を越えた検証に参加する前に、あらゆるシステムが備えなければならない特性です。MUSUBIはこの研究方針を誠実に名付けています：それが何になるかを過度に約束することなく、軌道を認識しています。信頼できる接続型インフラを構築する仕事は、信頼できるインフラを構築することから始まり、それがTSUNAGIの現在の取り組みの焦点です。

§6 持続可能な開発

TSUNAGIは、持続的な個人の取り組みを通じて構築されています。開発に資金を提供する制度的助成金なし、ロードマップを形成するベンチャーキャピタルなし、エンジニアリングの判断を上回るタイムラインを持つ外部ステークホルダーなし。この独立性は意図的です。プロジェクトの技術的決定が、資金サイクルや投資家の期待ではなく、正確性と長期的価値によって導かれることを保証します。

持続可能な開発とは、品質を維持し燃え尽きを防ぐペースで構築することを意味します。インフラソフトウェアは暗黙の約束を伴います：保守されること、動作が一貫していること、オペレータが何年にもわたる運用を通じて依存できること。その約束を信頼性をもって行うには、開発アプローチ自体が持続可能でなければなりません。TSUNAGIは、速度よりも正確性を、急速な機能蓄積よりも徹底的なテストを、アナウンスよりも動作するソフトウェアを優先します。出荷されるすべてのコンポーネントは、実装すると主張する動作に対して検証されています。

プロジェクトのトレジャリーは透明で公開文書化されています。独立したインフラ開発の財政的現実は、企業構造の背後に隠されたものではなく、プロジェクトの物語の一部です。この透明性は二つの目的を果たします：プロジェクトが誠実に運営されていることを示すこと、そして持続的な独立開発が実際に何を必要とするかの明確な像を提供することです。

TSUNAGIは、投機的な製品提案として構築されているのではありません。ライブネットワークに対して検証された決定論的実行、観察されたニーズから構築されたオペレータツール、資金要件ではなくエンジニアリングの判断によって導かれたアーキテクチャ上の決定に基づく、実際の実装作業に根ざした独立インフラの取り組みです。独立したエンジニアリングが何を生み出せるかを実証することで、Cardanoインフラの可能性を広げることを目指しています。

§7 今後の展望

TSUNAGIは初期段階のインフラです。Cardanoネットワークには、プライマリノードソフトウェアを補完する成熟した独立した実装がまだありません。そしてそれを構築することは複数年にわたる事業です。作業は進行中です — 各エポックが新しいプロトコル動作の検証、新しいエッジケースの処理、新しいサブシステムの構築をもたらします。実装の正確性への近道はなく、このプロジェクトはそうでないふりをしません。

ビジョンは長期的です。強靭なネットワークは単一の開発サイクルでは構築されません。持続的な取り組み、独立した検証、そしてソフトウェアが時間をかけて確実に、主張通りの動作を行うことから生まれる信頼の緩やかな蓄積によって構築されます。TSUNAGIは、検証済みの動作を一つずつ積み重ねて、その回復力に貢献します。Let It Run. Let It Resolve.
