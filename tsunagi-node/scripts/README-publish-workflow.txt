TSUNAGI Publish Workflow
========================

This document describes how content flows from the repository
to the live website at tsunagi.tech.

=== CONTENT MODEL ===

The site uses two content models:

  1. MARKDOWN-DRIVEN pages read content from a .md file at runtime.
     Updating the markdown file on the server updates the page.

  2. STATIC pages have all content embedded in the HTML file.
     Updating content requires editing the HTML and redeploying.

=== PAGE-TO-SOURCE MAPPING ===

  Page                  Model       Content Source
  ────────────────────  ──────────  ──────────────────────────────────────
  /whitepaper/          markdown    /docs/whitepaper/tsunagi-whitepaper.md
  /manifesto/           static      web/manifesto/index.html
  /roadmap/             static      web/roadmap/index.html
  /treasury/            static      web/treasury/index.html
  /status/              dynamic     /status.json (generated by script)
  / (homepage)          static      web/index.html

=== EXAMPLE UPDATE FLOWS ===

1. Update the whitepaper (markdown-driven):

   # Edit in repo
   vim docs/whitepaper/tsunagi-whitepaper.md

   # Copy markdown to server
   sudo cp docs/whitepaper/tsunagi-whitepaper.md \
     /var/www/tsunagi/docs/whitepaper/tsunagi-whitepaper.md

   # Done — page reflects changes on next load

2. Update the roadmap (static page):

   # Edit in repo
   vim web/roadmap/index.html

   # Copy HTML to server
   sudo cp web/roadmap/index.html \
     /var/www/tsunagi/roadmap/index.html

   # Done — page reflects changes on next load

3. Update the treasury (static page + markdown source):

   # Edit both files in repo
   vim docs/treasury/tsunagi-treasury.md
   vim web/treasury/index.html

   # Copy to server
   sudo cp web/treasury/index.html \
     /var/www/tsunagi/treasury/index.html

   # The markdown source is not served directly, but
   # keeping it in sync ensures consistency

4. Update status.json (generated):

   # Run the generator script
   TSUNAGI_HOME=~/tsunagi-home-preview \
     ./scripts/generate-status-json.sh /var/www/tsunagi/status.json

   # Or automate with cron (see scripts/README-status-json.txt)

=== WHICH PAGES READ MARKDOWN DYNAMICALLY ===

Currently only the whitepaper page fetches markdown at runtime:

  web/whitepaper/index.html
    → fetches /docs/whitepaper/tsunagi-whitepaper.md via XHR
    → renders to HTML using inline JavaScript
    → static shell provides: title block, abstract, TOC, LOF

All other pages are fully static HTML.

=== FUTURE: AUTOMATED PUBLISHING ===

A future improvement could automate the publish workflow:

  Option A — git pull on the server:
    ssh server "cd /path/to/repo && git pull"
    ssh server "sudo cp docs/whitepaper/*.md /var/www/tsunagi/docs/whitepaper/"

  Option B — webhook trigger:
    GitHub webhook → server script → git pull + file copy

  Option C — rsync from local:
    rsync -avz docs/ server:/var/www/tsunagi/docs/
    rsync -avz web/ server:/var/www/tsunagi/

These are not yet implemented. Manual copy is the current workflow.
